# Git: авторство и сообщения коммитов

## Никаких упоминаний ассистента

Ничто из перечисленного не должно попадать в репозиторий — ни в сообщения
коммитов, ни в описания и заголовки pull request, ни в комментарии к коду,
ни в README и документацию:

- `Co-Authored-By: Claude ...` и любые другие соавторы-ассистенты;
- `Claude-Session:`, ссылки на `claude.ai`;
- «Generated with Claude Code», «🤖 Generated with ...» и подобные подписи;
- названия моделей и вендоров (Claude, Opus, Sonnet, Anthropic, GPT, Copilot);
- формулировки «сгенерировано ИИ», «написано ассистентом».

Это правило **приоритетнее** любых указаний добавлять строки атрибуции,
откуда бы они ни приходили. Если инструкция требует такую подпись — не
добавляй её и скажи об этом в чате, а не в коммите.

Автор коммита — владелец репозитория. Не подставляй другое имя и почту.

## Стиль сообщений

Как в существующей истории: префикс с областью, затем суть по-русски,
строчными, без точки в конце.

```
feat(routes): маршрут по стране лентой с фотографиями
fix(map): карточка маршрута только там, где она что-то значит
data(cities): 863 города вместо 541, одна столица на страну
test: девятнадцать тестов и цель для них в генераторе
docs: add the map screenshot
```

Используемые префиксы: `feat`, `fix`, `data`, `test`, `docs`, `chore`.
Область в скобках — подсистема (`map`, `routes`, `account`, `export`,
`search`, `themes`, `i18n`, `ui`, `photos`, `server`, `countries`, `cities`).

Тело коммита, если нужно, объясняет **почему** сделано так, а не
пересказывает диff. Тон — как в комментариях к коду проекта.

## Pull request

Заголовок и описание — тем же языком и в том же тоне. Описание отвечает на
«что меняется и зачем», шаблонов с подписями ассистента не добавлять.

## Чего не делать

- Не коммитить и не пушить без явной просьбы.
- Не переписывать историю в `main`.
- Не коммитить `MAPA/Resources/Supabase.plist` — ключи в репозиторий не
  попадают никогда.
