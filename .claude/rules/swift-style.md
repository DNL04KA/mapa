# Стиль Swift в MAPA

Swift 5 (`SWIFT_VERSION = 5.0`), deployment target **iOS 16.0**, Xcode 14.2+.
Не используй API, появившиеся позже iOS 16, без `if #available` и запасного пути.

## Комментарии объясняют «почему», а не «что»

Это главная особенность кодовой базы. Документирующие комментарии (`///`)
написаны по-русски и объясняют принятое решение и его цену, а не пересказывают
сигнатуру. Пример из `Core/Plural.swift`: правила склонения лежат в
`.stringsdict`, «считать это руками — значит однажды написать „5 страна“ на
языке, которого не знаешь».

Пиши в том же тоне. Комментарий, пересказывающий имя функции, — лишний.

## Устройство типов

- `enum` без кейсов как пространство имён: `DS`, `Plural`, `AppLocale`.
- `struct` по умолчанию; `final class` только там, где нужна ссылочная
  семантика (`ObservableObject`, кэши).
- Доступ к данным — через протокол с файловой и эфемерной реализацией:
  `RouteStorage` → `FileRouteStorage` + `EphemeralRouteStorage`. Эфемерная
  нужна тестам и превью, добавляй её вместе с новым хранилищем.
- `public` в `DesignSystem` и `Core/Geo` — маркер «это API для остального
  приложения», а не требование модульности. Не расставляй его шире.

## Чего не делать

- Не использовать `!` для распаковки и `try!`. В проекте их нет — пусть так и
  останется. Для отсутствующих данных есть `guard ... else { return }`.
- Не добавлять зависимости. Проект собирается без единого пакета, и это
  осознанно: карта рисуется руками, без MapKit и тайлов.
- Не трогать `MAPA.xcodeproj/project.pbxproj` руками — он генерируется.
  После добавления или удаления файла: `python3 Tools/generate_project.py`.
- Не поднимать `IPHONEOS_DEPLOYMENT_TARGET` без явной просьбы.

## Формат

Отступ 4 пробела, `// MARK: -` для разделов внутри файла, один тип — один файл,
имя файла совпадает с именем типа. Структура каталогов: `App/`, `Core/`
(без UI), `DesignSystem/`, `Features/<Экран>/`, `Resources/`.
