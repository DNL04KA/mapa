# Конкурентность в MAPA

Язык — Swift 5, строгая проверка конкурентности **не включена**
(`SWIFT_STRICT_CONCURRENCY` в настройках отсутствует). Пиши так, чтобы код был
корректен и при её включении, но не добавляй аннотации «на будущее» пачками и
не включай строгий режим без явной просьбы.

## Правила

- UI и вью-модели — `@MainActor`. В проекте это основной инструмент (около 24
  применений), `DispatchQueue` не используется нигде. Не вводи его.
- Долгая работа уходит с главного актора через `Task.detached` с явным
  приоритетом: `.userInitiated` для чтения, `.utility` для записи. Так сделаны
  `FileRouteStorage`, `FileTravelLogStorage`, `WorldGeometryLoader`.
- `Task { }` внутри `@MainActor`-типа наследует главный актор — это нормально
  для коротких операций и обновления состояния. Для вычислений он не годится.
- Разделяемое изменяемое состояние — в `actor` (`RemoteImageStore`).
- `nonisolated` — только когда тип под ним действительно потокобезопасен, и
  с комментарием почему. Образец: `RemoteImageStore.memory` — `NSCache`
  потокобезопасен сам по себе.
- `@unchecked Sendable` — последнее средство. Есть ровно один случай
  (`MemoryCache`), и он объяснён комментарием. Новый такой случай требует
  такого же объяснения, иначе его не добавлять.

## Проверки перед сдачей

- После `await` состояние могло измениться: перечитай его, а не используй
  значение, прочитанное до приостановки.
- Захват `self` в `Task.detached` — явный и только для значимых типов; в
  хранилищах захватывается `fileURL`, а не хранилище целиком.
- Отмена: длинные циклы проверяют `Task.isCancelled`. Это важно для экспорта
  видео (`Features/Export/VideoExporter.swift`), который рендерит покадрово.
