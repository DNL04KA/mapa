# Хранение данных: SwiftData в проекте не используется

Deployment target — **iOS 16.0**, а SwiftData требует iOS 17. Пока цель не
поднята, `import SwiftData` и `@Model` в этом проекте невозможны. Не предлагай
их как решение и не добавляй ради них `if #available`.

## Что используется вместо

Хранилища спрятаны за протоколами, реализация — JSON в Application Support:

- `TravelLogStorage` → `FileTravelLogStorage` — отметки стран, личные.
- `RouteStorage` → `FileRouteStorage` — маршруты, в будущем общие.

Разделение намеренное: маршруты уедут на сервер, отметки останутся на
устройстве. Не объединяй их в одно хранилище.

## Правила для нового хранилища

- Протокол + файловая реализация + эфемерная (`Ephemeral...`) для тестов.
- Снимок в файле — отдельная `Codable`-структура с полями `version` и
  `updatedAt`. `version` обязателен: он единственный способ прочитать старый
  файл после смены формата.
- Запись атомарная: `data.write(to:options: .atomic)`.
- Даты — `.iso8601` и при кодировании, и при декодировании.
- Чтение и запись — вне главного актора, через `Task.detached`
  (см. `.claude/rules/concurrency.md`).
- Старый формат должен читаться. На это есть тесты в
  `MAPATests/RouteCodableTests.swift` — добавляй туда случай при смене схемы.

## Если SwiftData всё-таки понадобится

Это переход на iOS 17 и отдельное решение, а не деталь задачи. Условия: цель
поднята осознанно, протоколы хранилищ остаются, добавляется реализация
`SwiftDataRouteStorage` и одноразовая миграция из JSON. Сначала спроси.
