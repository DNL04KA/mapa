# Готовность MAPA к складному iPhone

> **О происхождении.** Оригинал skill с этим именем найти не удалось. В сети
> есть десяток одноимённых репозиториев разных авторов про iPhone Duo, ни один
> не является каноническим, и все они опираются на **SDK iOS 27.1**, которого
> в этом проекте нет. Содержимое ниже написано мной под MAPA и ограничено тем,
> что проверяемо на текущем SDK.

## Что в проекте сейчас

- `IPHONEOS_DEPLOYMENT_TARGET = 16.0`, сборка Xcode 14.2+.
- Цель приложения — только iPhone (`TARGETED_DEVICE_FAMILY = 1`).
- `UIScreen.main` не используется нигде — это хорошо.
- Размерные классы не используются **ни разу**: `horizontalSizeClass` и
  `verticalSizeClass` встречаются 0 раз. `GeometryReader` — 8 применений.

API складного iPhone (вертикальные панели, зоны шарнира, несколько дисплеев)
на текущем SDK недоступны. Поэтому skill не про них, а про то, чтобы смена
геометрии не ломала вёрстку, когда эти API появятся.

## Когда применять

Добавляется или переделывается экран; вёрстка разъезжается на другой ширине;
готовится поддержка складного устройства. Не применять для добавления
`#available(iOS 27, *)` — этого SDK в проекте нет, код не соберётся.

## Порядок действий

1. **Найди допущения о фиксированном размере.** Экран не должен считать, что
   ширина постоянна в течение жизни вью:

```bash
grep -rn 'UIScreen\|\.frame(width: [0-9]\{3\}' MAPA/Features --include='*.swift'
```

   Числа в `DS.Layout` — это отступы и размеры элементов, они в порядке.
   Проблема — это размеры, выведенные из экрана один раз и запомненные.

2. **Проверь GeometryReader.** Он даёт актуальный размер — но только если
   значение не кэшируется в `@State` без реакции на изменение. Проверь все
   8 применений: при смене размера значение должно пересчитываться.

3. **Карта — главный риск.** `MapCamera` ограничивает зум и смещение исходя
   из размера холста. При изменении размера нужно пересчитать ограничения,
   иначе карта останется за краем или зум упрётся не туда. Проверь
   `Features/Map/MapCamera.swift` и `WorldMapViewModel.swift`: есть ли реакция
   на изменение размера, или ограничения считаются один раз.

4. **Листы и панели.** `CountryStatusSheet`, `RoutePanel`, `SearchSheet`,
   `AccountSheet` рассчитаны на узкий экран. На широкой раскладке растянутый
   на всю ширину лист выглядит сломанным — ограничивай максимальную ширину
   содержимого, а не полагайся на ширину экрана.

5. **Проверь на разных размерах уже сейчас.** Без нового SDK это делается
   поворотом и разделением экрана на iPad-симуляторе либо превью:

```swift
#Preview {
    ЭкранView().frame(width: 320)   // узкая половина
}
#Preview {
    ЭкранView().frame(width: 740)   // широкая раскладка
}
```

6. **Размерные классы.** Если экран должен менять раскладку, а не только
   растягиваться, вводи `@Environment(\.horizontalSizeClass)`. Это доступно
   с iOS 16 и работает уже сегодня.

## Чего не делать

- Не добавлять `#available(iOS 27, *)` и API складного iPhone: их нет в SDK,
  проверка доступности отсутствующие символы не создаёт.
- Не поднимать deployment target ради этого skill.
- Не включать iPad в цель приложения мимоходом — это отдельное решение с
  отдельной работой по вёрстке.

## Как проверить результат

Экран снят на двух ширинах (узкой и широкой) без наезжающих элементов и
обрезанных подписей; карта после изменения размера остаётся в границах и
сохраняет центр; ни одно значение размера не запомнено в обход
`GeometryReader`. В отчёте — что проверено и на каких ширинах.
