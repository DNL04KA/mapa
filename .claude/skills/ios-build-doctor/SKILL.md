# Разбор сборки и падений MAPA

## Когда применять

`xcodebuild` или Xcode выдаёт ошибку, новый файл «не найден», приложение
падает при старте либо при открытии экрана. Не для правок логики — здесь
только диагностика.

## Первое, что надо проверить

**`MAPA.xcodeproj` генерируется скриптом.** Это источник большинства странных
ошибок сборки в этом проекте. Файл добавили в `MAPA/`, но в цель он не попал —
компилятор не видит тип, хотя файл лежит на диске.

```bash
python3 Tools/generate_project.py
```

Признаки: `cannot find 'X' in scope` при существующем файле; новый тест не
запускается; ресурс не найден в бандле. Правка `project.pbxproj` руками —
не решение, следующая генерация её затрёт.

## Порядок действий

1. **Прочитай ошибку целиком**, не только первую строку. У Swift первая
   ошибка часто следствие, а причина ниже.
2. **Проверь синхронность проекта** — команда выше. Сравни, что файл попал
   в цель:

```bash
grep -c "ИмяФайла.swift" MAPA.xcodeproj/project.pbxproj   # ожидается > 0
```

3. **Версия API.** Цель — iOS 16.0. Ошибки вида
   `is only available in iOS 17.0 or newer` означают, что применён слишком
   новый API: `@Observable`, SwiftData, `glassEffect`. Решение — найти путь
   для iOS 16, а не поднимать `IPHONEOS_DEPLOYMENT_TARGET`.
4. **Ресурсы.** Карта и каталоги читаются из бандла:
   `world_110m.geojson`, `cities.json`, `country-facts.json`,
   `city-facts.json`. Падение при старте с пустой картой — обычно ресурс не
   попал в цель (см. шаг 2).
5. **`Supabase.plist`.** Его нет в репозитории, и это нормально.
   `BackendConfig.current` возвращает `nil`, приложение работает без сервера.
   Падение из-за отсутствия файла — ошибка в коде: значит где-то распаковали
   `nil`, и чинить надо это, а не добавлять ключ в репозиторий.
6. **Чистая сборка**, когда ошибка не воспроизводится в чистом дереве:

```bash
xcodebuild clean -project MAPA.xcodeproj -scheme MAPA
rm -rf ~/Library/Developer/Xcode/DerivedData/MAPA-*
```

7. **Падение.** Нужен символизированный стек. Смотри кадр в коде MAPA, а не
   в системных фреймворках: `Data(contentsOf:)` при отсутствующем файле,
   декодирование JSON с изменившейся схемой, индекс за границей массива в
   геометрии.

## Как проверить результат

Собери заново и покажи вывод. Названа конкретная причина и конкретная правка;
«почистил DerivedData, стало работать» — не диагноз, если не понятно, что
именно было рассинхронизировано. На Linux `xcodebuild` недоступен: разбирай
по тексту ошибки и скажи, что сборку подтвердить не можешь.
